## 设计树

1. 单页的展示标准：桌面核心指标首屏完成、手机纵向滚动，已采纳。
2. 概要内容分组：资产规模、CVE、生命周期风险、评估覆盖/待处理，已采纳。
3. 统计单位与默认范围：沿用 current 统计，未知与未评估分别表达。
4. 下钻入口与筛选传递：依赖页面职责与导航事实调查；确保看到的数字与详情属于同一客户和同一统计范围。
5. 验收与实施边界：按四张任务的公开行为和端到端用例验收。

## 原则与事实

- 术语“客户风险概览”已记录于 GLOSSARY.md。
- 已有统计区分漏洞匹配记录、唯一 CVE、已确认受影响资产、未评估和未知；精简视觉时不能把这些数混称为漏洞总数或零风险。
- 布局和导航属于可逆的产品调整，当前不需要新增 ADR。

## 当前页面实测

只读检查线上页面，1440×900视口下页面高度2932px，存在2张表和4个选择器。主要包含生命周期风险、容器扫描、严重度分布、覆盖/新鲜度、EOS/EOL、对象与证据及历史趋势。截图保存在忽略目录 `output/deployment/dashboard-before-onepage-1440.png`。

## 导航事实调查

- `#risk` 目前只以“风险结果”标题复用 DashboardPage，尚不是独立的明细实现。精简首页前必须分离两者，避免同时丢失详情。
- 生命周期卡片可携固定view ID和level跳转生命周期风险页；容器摘要可跳容器页。
- CVE对象下钻、观测记录、固定证据和历史趋势目前在概览本页展开。通用导航仅支持asset/snapshot/profile，尚未支持固定assessmentRefs、严重度和日期范围。
- 因此卡片跳转需要补齐对应页面承接和统计范围传递，不能只把长页面下面的内容隐藏。
- 原 docs/dashboard.md 的默认批次规则落后于当前实现；当前代码使用 selectionMode=current。后续明确统计口径时需同步文档，不根据旧说明重写默认规则。

## 已批准的任务拆分

任务已发布于 niwaip/ys，原生子任务和依赖记录见 `docs/tracking/dashboard-onepage.json`。

1. **独立风险结果页承接完整详情**。无阻塞。首页与风险结果职责分离；现有对象、观测、趋势与证据可在风险结果页独立访问。URL/导航保留客户及固定评估范围，刷新后仍可回读，跨客户引用由后端拒绝。先完成必要职责拆分，不丢失旧页面能力。
2. **单页概览与资产、评估覆盖卡片闭环**。阻塞：1。桌面1440×900核心区首屏、手机390纵向排列；首页不显示明细表/日志/证据/批次配置。资产规模与评估覆盖数字通过现有聚合接口取得，点击跳转对应台账、评估或风险结果页并保留筛选。失败、未评估、未知分别表达，不以0替代不可用数据。
3. **CVE数字卡片与同范围等级下钻**。阻塞：2。展示有明确单位的唯一CVE及严重度匹配记录，点击等级进入对应风险明细；补齐严重度筛选、固定assessmentRefs及时间/对象范围的传递、分页和刷新。指标与详情可核对，不把工具匹配记录当作已确认受影响资产，也不累计重复历史批次。
4. **生命周期风险概要与对应明细跳转**。阻塞：2。在一屏概览内显示生命周期风险等级和待处理概要，沿用固定风险视图并跳转对应筛选的生命周期风险页；资产数与风险项数明确区分，多类型风险不重复冒充资产数。不把风险接受视为风险解除。完成四组摘要后再次验收整体首屏和手机布局。

每项都交付可演示的公开接口→页面→详情跳转行为及相应自动化验证；不拆出独立“只做测试”的末尾任务。3和4互不阻塞。已应用 ready-for-agent 标签及原生阻塞关系。
