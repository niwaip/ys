# 评估体验验证

日期：2026-11-22。实施规格：`docs/specs/assessment-experience.md`。

## 实施结果

- 统一评估对象选择；按资产及客户限定 Linux/Windows 输入资料。网络设备明确披露固件评估尚不支持；资料缺失、读取失败、读取中分别显示。隐藏不支持的执行入口时保留历史。
- 默认组件分组；完整匹配记录与去重 CVE 分别计数，保留版本/架构身份、等级分布、展开与分页。筛选响应过期时不自动选择旧组件。
- AI 分析支持 Markdown 标题、列表、表格、代码与复制；过滤 HTML、图片及危险链接。失败阶段和下一步来自已保存任务信息，不补造历史失败原因。
- 来源先展示站内已有依据和摘要，再由用户打开原文；未重新抓取原文时明确说明。

## 验证

- `npm test`：27 个文件、72 项测试通过。
- `npm run typecheck` 与 `npm run build`：通过。Markdown 按需加载。
- 浏览器针对性回归覆盖单次选择、网络设备、资料读取失败、对象读取失败、分组筛选切换、分页、来源查看、Markdown 渲染与复制、危险内容过滤、历史回读及客户隔离。
- Standards 与 Spec 两轴独立复核完成；发现的过期分组选择和资料失败状态问题已修复并增加浏览器回归，复核无阻断项。

## 验证边界

使用固定扫描器与 AI 响应测试夹具验证页面和接口；没有验证生产模型的实际回答质量。没有部署到线上，也未改变线上扫描记录。现有扫描匹配仍需运行环境证据才能判定实际受影响，组件分组不会将匹配数改称已确认漏洞数。
