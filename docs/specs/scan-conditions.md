# 完整扫描条件区

实施基点：`4dc2116`。用户在设计建议后调用 implement，按推荐方案实施。

- CVE 评估以同一张“扫描条件”卡片组织评估对象、四类扫描内容、对应输入条件、支持状态、执行按钮及提交错误。任务进度、结果、历史放在卡片之外。
- 保持单对象评估。资产列表的翻批控件放入选择器下方折叠项，仅存在多批时显示；不暗示批量执行。来自资产详情的固定对象仍可切换。
- Linux 自动使用执行时最新资料，并展示当前最新资料编号、导入时间、系统与包数量；不会重新采集。当前预览不保证提交前没有新资料，最终任务绑定实际使用的固定快照。
- Windows 在卡片内明确选择主机快照及规则版本；规则导入放入可选折叠准备区。软件选择对象与 SBOM 版本；资产关联软件/镜像保留固定关联版本的执行入口。
- 独立镜像评估在卡片内选择已有镜像和版本并执行；新建对象和上传 SBOM 留在镜像资料管理入口，镜像详情、组件及评估历史在条件区之外。
- 四类扫描内容均可见。读取中、失败、缺资料与不支持的原因保持区分；网络设备不伪装成有固件扫描能力。不支持的扫描入口继续隐藏或禁用，历史仍可查看。
- 关注等级只筛选结果显示，不是扫描条件；放在条件区之外并明确标注。保留现有任务幂等、资料归属、客户隔离及历史范围。
- 沿用已有浏览器与 HTTP 验证边界；不变更扫描引擎、接口协议或自动部署。
