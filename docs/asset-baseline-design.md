# 采集确认与资产基线设计（讨论稿）

2026-11-19，用户随后调用implement，按推荐方案实施。本轮用户要求：采集后用户确认、更新基础数据及NetBox；资产台账展示具体资料；资料分层改为可见区块；再次采集突出变化。

## 已明确的业务含义

采集观测保存原始事实、来源和覆盖；用户采纳后形成资产基线，再次采集比较最近已确认基线。该确认与报告内部复核分别处理，不修改原始采集记录或风险判定。未采集、失败、权限不足不能作为删除依据。

## 建议交互

从台账打开资产详情，以资产为中心提供概览、资料区块、变更和采集历史。顶部显示当前基线、最新采集、待确认变化及各层覆盖。OS、硬件、网络、Docker版本、系统包、容器/镜像目录均显示可见区块和状态，使用页内锚点导航；不再用下拉选择资料分层。大量包默认显示数量及变更摘要，进入可搜索分页表，原始证据折叠。

首次采集展示待确认资料与缺口；后续采集展示基线值、采集值及新增/删除/变更。默认突出变化，可切换全部资料。确认前不更新基线；确认后记录采纳人、时间、来源及版本，保留历史基线。

## 已采纳决策

1. NetBox负责可映射资产主数据；系统包、运行观测等完整基线及来源由YS保存并从资产详情统一展示。写回使用明确字段映射，不能靠名称猜测；是否接受此职责边界？
2. 默认按资料区块采纳，可展开字段排除；首次全部有效区块默认选中。失败/未取得不能覆盖已有资料；是否接受此确认粒度？
3. 固定页面基础采集默认直接工具，Pi用于对话/可选协助，二者使用相同固定采集器和结果规范；是否接受此调用方式？

## 实现边界

首批NetBox映射为明确采纳的主机名和序列号；OS/包及其他观测基线保存在YS。失败/响应丢失保持unknown、阻止后续采纳，提供只读核对后完成。包比较使用管理器、名称、架构，不按版本产生删除/新增假象。见ADR003。
