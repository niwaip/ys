# 生命周期风险页面设计草案

状态：用户已通过 implement 技能授权完整实现与端到端验证。

## 已确认范围

页面统一称为“生命周期风险”，覆盖操作系统停止支持、设备停止支持、维保到期、购买后使用年限四类风险。风险概览 Dashboard 展示概要，此页承载详细信息及规则配置。

## 日期资料归属

产品及版本的厂商支持终止日期在生命周期基础资料中维护。购买日期和维保到期日期在具体资产资料中维护，本页引用并链接至来源。已接入 NetBox 的字段沿用其主数据归属，避免重复维护。

使用年限按设备类别配置，由购买日期加设定年限推导到期日期。不设统一报废年限；未配置年限或缺少购买日期时显示“待补资料”。

## 规则范围与生效

每个客户配置默认阈值，OS、服务器、网络设备等类别可覆盖默认规则。每项风险采用一套有效规则，详情显示实际采用的规则。

保存前预览影响范围，保存后重新计算当前风险，之后每日更新。Dashboard 和风险明细使用同一批计算结果并展示更新时间。历史评估与报告保留原结果，不被当前风险重算覆盖。

## 分级与资料异常

默认提前 12 个月提醒、提前 6 个月警告，到期当天起致命，阈值可配置。按自然月计算，月底取目标月最后一天；按客户时区判断日期，默认北京时间。“致命”表达生命周期规则等级。

日期缺失显示“待补资料”，来源日期冲突显示“资料冲突”，均不归入正常或自动判为致命，并提供来源查看与修正入口。

## 风险处理

第一版处理状态为待处理、处理中、已接受风险，记录负责人和备注。接受风险必须填写原因及有效期。处理状态不降低风险等级；只有日期、资产情况或规则变化使其不再命中时，风险才解除。第一版仅做站内展示。

## Dashboard 统计

同时展示风险资产数和风险项数。同一服务器命中 OS 与维保风险时，计为一台风险资产、两项风险。资产按最高等级归类；已接受风险仍计入总数并单独标识。概要数字跳转到本页相应筛选结果。

## 页面结构

默认打开“风险明细”页签，顶部展示致命、警告、提醒、资料异常概要。支持按风险类型、设备类别、等级、处理状态、负责人筛选及搜索资产。

列表一行一项风险，展示资产、风险对象、到期日期、剩余时间、等级、处理状态、负责人，默认按等级及到期日期排序。正常项通过筛选查看，默认聚焦风险与资料异常。

详情抽屉展示日期来源、支持阶段、命中规则、处理记录及资产入口。“规则配置”为第二页签，维护客户默认规则、类别覆盖及使用年限。

## 规则停用与接受到期

停用规则后，对应项目标为“不评估”，不计入当前风险，保留历史记录，并单独展示未评估数量。规则保存预览同时展示风险数量和未评估数量变化。

风险接受有效期届满后，风险仍存在则自动回到“待处理”，保留接受记录、负责人和备注；已解除的风险保持解除结果。

## 实现前约束

当前风险与历史评估分别表达，不能通过每日重算改写历史报告依据。提醒阈值重叠时采用最高等级，资产概要亦采用其风险项中的最高等级。

本草案记录业务方案；具体接口、任务执行与权限接入沿用项目约定，在实现前核对。

## 接口与运行方式

新增导航“生命周期风险”，保留原 EOSL 手工评估与生命周期资料入口。当前期限风险在 Dashboard 独立展示，明确与所选历史评估范围分别统计。

客户接口前缀 `/api/customers/:customerId/lifecycle-risk`，沿用操作员鉴权与客户隔离：

| 请求                             | 行为                                                             |
| -------------------------------- | ---------------------------------------------------------------- |
| GET `/config`                    | 当前客户默认规则、类型/类别覆盖、使用年限与时区                  |
| POST `/preview`                  | 完整配置，返回保存前概要、预览快照与变化项数，不写入             |
| PUT `/config`                    | 保存完整配置并原子重算，返回新快照                               |
| GET `/current`                   | 按当前资料计算并保存新风险快照                                   |
| GET `/latest`                    | 读取已保存的最近快照，无快照时首次计算                           |
| GET `/views/:id`                 | 读取固定快照，不重新计算                                         |
| PUT `/treatments/:assetId/:type` | 保存当前命中风险的处理状态、负责人、原因及接受有效期，返回新快照 |

资产资料通过 `PATCH /api/customers/:customerId/assets/:assetId/lifecycle` 维护。购买及维保日期使用 YYYY-MM-DD；OS、设备支持关联明确的批次、产品、版本及 eos/eol 栏位，详情显示原始阶段名称。OS 未知版本不产生已核实支持日期。日期异常分别保留，不以无效 OS 关联抹去有效维保日期。

NetBox 模式拒绝本地资料写入，读取原生 Device/VirtualMachine 的 `custom_fields.ys_lifecycle` JSON 对象，结构与资产生命周期资料一致；需要在已有 NetBox 中自行配置该字段后同步。无效/跨客户来源不会泄露资料，保持缺失状态。未配置 NetBox 的环境保留本地维护。

后台进程每分钟检查客户当地日期，跨日或尚无快照时更新；停机期间不执行，恢复后下一轮补算当前日期，不伪造停机期间历史。保存规则及显式更新立即计算。接受有效期包含所选日期，次日风险仍命中则恢复待处理。

每个快照含固定配置、计算日期、风险项与依据。Dashboard 下钻携带快照编号及筛选等级，因此概要与明细可精确核对。处理固定快照中的风险前需切换到当前风险。
