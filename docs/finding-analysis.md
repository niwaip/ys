# 漏洞结果一览与 AI 解析（#25–#28）

当前结果先于历史；概要显示发现数量、覆盖与数据库时效，技术标识收进证据详情。完整结果支持 CVE、组件名、安装版本的字面量检索与等级组合筛选，先过滤再分页，默认高危和致命。修复版本指工具提供的版本，不代表已经验证升级。

单条记录的解析绑定 customerId、assessmentId、findingId、输入版本、输入与工具输出 hash，并保存 factHash。Pi 通过固定技能和工具读取有限事实、保存结构化解析；解析包含漏洞说明、系统影响（明确为推断）、待核实条件及建议计划。解析不改变工具判定、不执行修复、不确认基线、不写 NetBox。

公开情报由后端固定查询能力执行，不把客户资料交给公共查询。来源与查询时间绑定解析，模型只能引用后端提供的来源编号；失败明确披露后继续现有证据解析。未取得运行状态、暴露面、补偿措施时不宣称已验证受影响。

重开复用已保存解析；重新解析创建新任务，失败不覆盖旧成功结果。新扫描是独立对象，不继承旧解析。任务持久排队、客户鉴权、幂等、超时、重启中断和状态更新均需覆盖。

## 公开资料查询

配置 YS_CVE_SCRIPT 时复用既有 Pi 固定公开查询能力；未配置时，以固定 CVE 编号查询 [CVE Services 生产 API](https://github.com/CVEProject/cve-services/blob/dev/docs/architecture-diagram.md) 的单条 CNA 记录。固定主机、禁止重定向、12 秒超时、1 MB 上限，不抓取来源中的任意链接。仅查询单个合法 CVE 编号，客户和资产信息不会发送给公开查询。CNA 单来源保持部分覆盖，网络失败明确显示资料不可用。

解析状态通过轮询持久任务更新，扫描进度继续采用既有 SSE。每条记录首次点击 AI解析即创建任务；重开复用保存结果，手动重新解析创建独立任务。Pi 仅接收所选记录的有限事实、漏洞说明及允许引用来源，不接收全量漏洞原始报告。

## 运行约束

沿用现有部署方式：每个数据库只运行一个 API 服务进程。启动时将上次运行中任务记为中断；不支持多个 API 进程同时消费同一数据库的队列。解析保存最近 20 次尝试及最后一次成功结果，因此连续失败不会使已保存成功结果在重开时消失。
