# 生命周期资料工作台规划

状态：用户implement指令确认推荐拆分与余下建议，正在实现并验收。

## 已确认的业务划分

页面以具体资产的生命周期资料为主，厂商参考资料为辅。资料分为两类：

- 共享生命周期资料：厂商针对OS、软件、设备型号、硬件产品及适用版本公布的支持阶段期限。共同资料通过CSV校验后直接导入，不增加单独预览步骤。
- 资产专属期限：具体设备的购买日期、维保期限及使用年限等。按设备手动填写并直接确认保存，不增加第二轮预览。

用户第二轮答复修正了最初“所有输入统一预览确认”的建议，不能将该建议作为已接受需求。相同型号不等于相同购买日期或维保日期。

## 现有事实与边界

现有生命周期页面的CSV是厂商产品/版本参考资料批次，不是资产期限批量录入。设备购买日期与维保日期已在资产生命周期表单维护；OS与设备支持期限通过共享批次、产品、版本和阶段关联。软件生命周期已有独立输入版本的评估入口。

目前NetBox管理资产禁止写本地生命周期副本；资产列表已有设备类型筛选，但无生命周期填写状态筛选。风险的“待补资料”含无法计算期限等情况，不等同“没有填写”。

## 页面方向

上方为覆盖概览，下方为按设备类型和资料状态筛选的资产明细。共同资料与个别资料使用分别命名的操作入口，避免把导入厂商期限、填写购买日期和风险评估混为一件事。厂商参考资料保留来源及历史批次。

## implement指令采纳的建议

1. 产品/型号、版本和明确阶段唯一精确匹配时自动引用；缺版本或多来源保持待确认，显式批次关联优先，旧评估不改写。分类CSV增加category（os/software/device/hardware）和phase（eos/eol）；旧CSV仍可按明确来源关联，不根据阶段缩写猜测引用阶段。
2. 沿用台账设备分类，支持未填写/待补充/完整、缺购买日期、缺维保日期、缺支持资料、未匹配与冲突筛选。填写状态表示当前适用资料覆盖：个别日期与适用支持资料均具备有效值才完整；有效部分保留，无效字段单独提示。
3. NetBox资产通过YS填写、写回ys_lifecycle后回读；保留其他字段与身份，失败不写本地副本并记录未确认历史。共同参考资料保存在YS。
4. 设备专属日期留空不清除旧值，保存记录操作员及前后版本；旧表单以expected快照核对并拒绝覆盖新值。新的采集、导入和填写不自动触发风险评估。
