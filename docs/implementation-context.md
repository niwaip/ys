# 实现约定

用户于 2026-11-18 显式调用 implement-spec，授权按规格及 T01–T15 的任务图开始代码实现；此前仅设计的限制对本次本地实现已解除。服务器部署、现有主机验证和真实客户扫描仍不在授权范围。

## 来源与验收

- 业务来源为资产风险平台规格、任务清单和术语表。
- 主验收边界采用后端对前端公开的业务接口，辅以少量关键浏览器交互；工具接入在其公开输入输出契约处验证。
- 按 TDD 逐个用户行为先获得失败证据，再实现使其通过。自动测试可替代外部进程和情报源，但不能把模拟数据伪装成真实扫描。
- 技术方向使用 TypeScript、React + Vite、NestJS、Node.js 与 PostgreSQL；没有采用的建议需记录原因。
- 本地进程、隔离测试数据库和固定样例允许用于实现验证，不连接已有服务器或客户目标。

## 协作与集成

- 每个任务在基于 ys/integration 的独立工作树和分支中实现，提交前合入集成分支最新状态。
- 任务完成后由独立合并代理将提交并入 ys/integration。
- 数据、接口、前端与测试按业务功能组织；不将业务全部塞进单个应用文件。
- 共享契约只放稳定的业务输入输出；新增能力优先复用已经落地的持久化、身份与执行语义。
- 后续任务新增页面通过可组合的功能导航接入，避免重写整个主页面。
- 凭据、运行输出、真实客户资料和扫描缓存不提交仓库。

## 功能限制

- 所有涉及客户的数据由后端验证归属与权限，不能仅相信前端或提示词。
- 软件、容器、主机评估与公开情报查询保持不同的业务语义。
- 报告复核不修改评估判定。未知、失败、未扫描和零发现保持区分。
- 不安装或部署旧 YATA 系统，不直接复制生产配置或密钥。
