# T11：重扫后查看历史并比较评估版本

状态：已发布为 GitHub #12，进入实现。

https://github.com/niwaip/ys/issues/12

## What to build

同一软件对象有新资料或重新评估时，查看每次结果与其依据，并比较发现的变化。

## Acceptance criteria

- [ ] 同一对象的资料版本、任务和评估批次分别可识别，新评估不覆盖旧批次。
- [ ] 列表优先返回摘要，选择某批次后按需读取组件、漏洞和证据。
- [ ] 用户可明确选择两次评估，看到新增、持续和本次未再观察到的发现及关联版本。
- [ ] 未再观察到不直接标记已修复；比较同时展示输入范围、工具或库时间及覆盖变化。
- [ ] 选定当前纳管版本或快照与历史查询具有明确关系，跨客户数据不能混入比较。
- [ ] 通过接口和页面验收重扫、版本变化、失败批次及重复发现的计数。

## Blocked by

- T05：从页面执行 Trivy 软件评估并保存结果

## Scope notes

本片先比较一种已支持的软件评估；跨工具复杂合并和资产自动删除不在本片内。

每条任务通过业务接口和必要页面行为验收；相关持久化、执行逻辑和测试随该行为共同交付。客户归属、来源追溯和失败语义从本片开始落实，不推迟到统一补丁任务。

对应规格 User Stories：18、20、25、26、34。

发布标签为 ready-for-agent。用户已调用 implement-spec 授权本地实现；服务器部署和真实客户扫描仍需另行明确指令。
