# T12：按客户查看可下钻的风险 Dashboard

状态：已发布为 GitHub #13，进入实现。

https://github.com/niwaip/ys/issues/13

## What to build

从客户概览查看资产、组件、CVE、生命周期、覆盖及趋势，并下钻到对象和证据。

## Acceptance criteria

- [ ] 借鉴 Dependency-Track 的组合与逐层下钻方式，当前客户、版本或快照及时间范围可见。
- [ ] 首片展示资产与组件、CVE 分布、EOS/EOL 状态、任务与覆盖、资料新鲜度；空数据和未支持模块不显示成零风险。
- [ ] 区分唯一 CVE、漏洞实例、确认受影响对象和历史扫描行数，统计可对应实际明细。
- [ ] 版本或快照筛选后，汇总和下钻使用相同范围；风险趋势同时呈现覆盖范围变化。
- [ ] 不引入人工抑制、临时 AI 分数或报告复核导致的风险统计变化。
- [ ] 通过业务接口与关键页面验收指标明细一致、客户隔离、缺口及跨版本趋势。
- [ ] 首片不提供未经决定的全客户合并视图；保留未来扩展的接口空间。

## Blocked by

- T08：导入生命周期主数据并展示 EOS/EOL 评估
- T11：重扫后查看历史并比较评估版本

## Scope notes

先实现有限卡片、一个分布视图、一个趋势视图和明细入口；布局与计算口径需随本片具体化。

每条任务通过业务接口和必要页面行为验收；相关持久化、执行逻辑和测试随该行为共同交付。客户归属、来源追溯和失败语义从本片开始落实，不推迟到统一补丁任务。

对应规格 User Stories：39、40、41、42。

发布标签为 ready-for-agent。用户已调用 implement-spec 授权本地实现；服务器部署和真实客户扫描仍需另行明确指令。
