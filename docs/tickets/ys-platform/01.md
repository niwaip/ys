# T01：按客户创建和查看一项资产

状态：已发布为 GitHub #2，进入实现。

https://github.com/niwaip/ys/issues/2

## What to build

在工作台选择客户，手工建立一项资产并刷新查看；不同客户的同名资产保持独立。

## Acceptance criteria

- [ ] 提供最小可运行的前端、后端及持久化路径，页面显示当前客户，资产创建和读取跨刷新有效。
- [ ] 客户归属由后端校验；无权限、缺失或不匹配的客户与资产引用不能读写其他客户的数据。
- [ ] 只建立必要的核心信息、扩展属性和稳定内部引用；区分系统身份与名称等来源标识。
- [ ] 明确首片采用的资产主数据来源：复用 NetBox 或本地最小资产记录；记录依据，不同时维护两份权威台账。
- [ ] 落地本片实际需要的 TypeScript、Node.js 与前后端功能模块约定，不预先搭建全部模块。
- [ ] 通过业务接口验收客户隔离、同名对象区分和保存回读，并以少量页面测试验证客户切换。

## Blocked by

None (can start immediately)

## Scope notes

首片只覆盖一个资产类型和最小操作人员使用路径；客户自助门户、完整 DCIM/IPAM 和大规模权限管理不在本片内。

每条任务通过业务接口和必要页面行为验收；相关持久化、执行逻辑和测试随该行为共同交付。客户归属、来源追溯和失败语义从本片开始落实，不推迟到统一补丁任务。

对应规格 User Stories：1、2、3、4、5、17、58、60。

发布标签为 ready-for-agent。用户已调用 implement-spec 授权本地实现；服务器部署和真实客户扫描仍需另行明确指令。
