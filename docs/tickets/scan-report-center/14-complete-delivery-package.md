# 14: 打包并交付 PDF、HTML、XLSX 与可选附件

## What to build

在报告详情下载默认 ZIP 报告包，区分草稿与正式交付，检查包完整性并处理单格式失败。

## Acceptance criteria

- [ ] 默认 ZIP 包含总报告 PDF、离线 HTML、完整 XLSX 及文件清单/校验值；已接入的分报告和证据能力通过所选产物纳入，不虚构尚未完成的附件。
- [ ] 全部文件来自同一固定事实及明确修订；清单记录实际选择、文件与校验值，离线打开必要内容可用。
- [ ] 草稿包及其中报告文件标明未复核；正式包绑定已复核修订并完成正式交付，保存操作人与时间，重复下载不重扫。
- [ ] 默认必选文件及所有勾选附件全部成功后才显示包完整，某格式失败可重试，保留已成功产物。
- [ ] 允许明确下载可用部分并标明不完整；附件失败可重试或明确取消选择后重建清单，不能静默遗漏。
- [ ] 扫描覆盖与包完整性独立：80/100 台有结果仍可生成文件齐全的包，但所有呈现继续披露 20 台缺口。
- [ ] 打包状态可刷新回读，授权失效拒绝新下载或交付，不提供公开分享链接；同一授权操作员允许生成与复核。
- [ ] 公开 API、真实浏览器及解包核对默认文件、所选产物、校验值、失败重试和草稿/正式状态；本片可在未安装可选附件能力时独立交付默认包。
