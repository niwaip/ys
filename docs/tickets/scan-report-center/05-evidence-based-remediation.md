# 05: 有依据的整改建议与可选 AI 摘要

## What to build

报告给出可追溯的整改优先事项及复测建议，并可让已有 AI 能力辅助组织摘要；AI 不可用时仍能完成报告。

## Acceptance criteria

- [ ] 依据绑定评估和带来源的修复资料给出动作、关联对象、修复或升级依据及复测方式，不将无依据建议写成确定修复事实。
- [ ] 按严重程度、确认影响及已有业务重要性组织优先级，缺少业务重要性保持未知；没有修复依据标为待核实，不编造版本、补丁、日期或风险解除结论。
- [ ] AI 复用已有受控叙述与事实保护，仅辅助组织摘要和解释；扩展允许表达时保留引用及证据条件校验。
- [ ] AI 未配置、失败或提案无效时保留固定模板及诊断，用户仍可预览、复核和交付；AI 成功仅形成需复核的新修订。
- [ ] 整改内容在页面与报告中一致展示、可供明细表导出复用；首期不新增完整工单系统或隐含负责人/SLA 事实。
- [ ] 公开 API 和浏览器验证有/无修复依据、未知业务重要性、AI 可选失败路径及事实保护；外部模型使用隔离替身。
