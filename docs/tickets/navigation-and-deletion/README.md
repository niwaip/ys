# 资产删除与业务导航：任务拆分草案

2026-11-19。状态：用户调用implement接受拆分及推荐边界；已发布GitHub #19–#24，建立原生阻塞关系并进入实施。

任务系统：niwaip/ys GitHub Issues，批准后每项一条 issue，ready-for-agent，阻塞关系使用原生 dependencies。本轮由对话提出，不擅自修改或关闭现有规格 #1/#18。

## 待确认的推荐边界

- 第四模块为“风险与报告”；软件漏洞评估在第三模块，软件及组件资料在第二模块。
- 删除表示从YS移除纳管、可恢复并保留历史；不删除NetBox原生对象，再同步不自动恢复。
- Dashboard默认当前客户全部在管资产；“全部CVE”指该客户评估结果涉及的CVE，并非公开漏洞库全集。当前风险统计与历史版本统计明确区分。

用户随后调用implement，按上一轮明示的推荐边界实施。本轮Dashboard为当前客户，不启用跨客户统计。

## 01 从台账删除与恢复资产，保留历史依据

**交付：** 用户从台账删除资产，经确认后退出默认列表与新采集/评估选择；在已删除列表中可查看历史并恢复。

**Blocked by：** 无。

验收：
- 本地及NetBox模式均可操作；仅对当前客户有权限的资产有效，界面明确影响及历史保留规则。
- 删除状态持久化，记录操作者及时间；再次同步不自动恢复，不修改NetBox原生对象或共享软件/SBOM对象。
- 快照、基线、已有关联、评估、报告及来源链可读取；不级联破坏历史。
- 删除资产不能新建采集、关联、基线写回、资产关联评估或选择为当前在管对象；独立共享软件仍可评估。
- 明确阻止删除仍有运行中采集/评估或待核对写回的资产，避免并发任务重新更新已删除资产；状态检查与删除需防并发竞争。
- 恢复保留原身份；NetBox映射已失效时显示状态并阻止新采集，不能伪装成有效映射。
- HTTP、持久化、跨客户、同步和浏览器删除/恢复验收通过。

## 02 按四个业务模块组织导航，以Dashboard为首屏

**交付：** 登录后进入Dashboard；菜单分为总览、资产管理、CVE与EOSL评估、风险与报告。

**Blocked by：** 无。

验收：
- 现有页面都有明确归属并可访问，不重复暴露软件评估入口。
- 旧入口、刷新、返回和客户切换行为可用；迁移期间保留必要的入口兼容。
- 桌面和手机分组清晰，当前页高亮，菜单往返无空白或异常。
- 此任务先以现有页面接入分组，不依赖后续工作区升级。

## 03 统一资产资料工作区与采集入口

**交付：** 从资产管理进入台账、采集、容器/镜像、软件/项目和生命周期基础资料；从具体资产进入其资料分层。

**Blocked by：** 02（导航中已有资产管理分组）。

验收：
- CSV、Windows导入、脚本上传、手动及连接采集归入相应页面内入口；收拢旧入口时仍可完成原流程。
- 硬件对象能区分服务器与网络设备，支持明确类型建档/映射；历史host数据无依据时不自动改成网络设备，缺少映射不按名称猜测。
- OS、Package、Docker环境、容器、镜像、软件组件及生命周期资料按所属对象呈现，保留来源、版本及采集状态。
- 网络设备可建档或导入已有资料；当前Linux网卡采集不冒充交换机/路由器采集。SNMP及厂商专用采集不在本任务范围。
- 已有台账详情只读、采集结果确认后更新基线的边界保持；SBOM须明确关联对象版本。
- 生命周期基础资料的维护入口与执行评估入口分别可用；浏览器完成资料进入、导入与回读。

## 04 提供统一CVE与EOSL评估工作区，并从资产发起

**交付：** 用户从评估模块或资产操作入口选择明确对象、固定输入版本与评估类型，提交已有能力支持的任务并查看结果。

**Blocked by：** 02（评估模块入口）。

验收：
- 汇集已有软件SBOM、镜像SBOM、Windows补丁CVE评估及EOSL评估；不重复实现现有执行器。
- 从资产发起时保留资产及明确关联的输入版本；不能误选同客户其他主机的软件版本作为部署事实。
- 显示支持范围、配置状态、排队/执行/失败/完成、覆盖和证据；未配置或不支持不展示为零风险。
- 主机Linux原始包清单与运行容器组件扫描的现有限制明确显示；新扫描适配器另行立项。
- 结果与固定输入版本绑定，可刷新回读及查看历史，保持客户隔离；单独发起软件评估仍可用。
- EOSL针对已维护的生命周期资料执行匹配，与资料维护分离。

## 05 建立风险与报告工作区

**交付：** 用户集中查看已有漏洞/生命周期风险、影响对象、历史差异，开展分析并从所选事实生成报告。

**Blocked by：** 02（风险与报告模块入口）。

验收：
- 接入已有评估结果、历史比较、客户风险对话及报告能力；没有结果时显示未评估状态。
- 可追溯CVE到受影响资产、软件/镜像版本及组件；同一CVE与多个受影响对象分别计数和展示。
- 报告保留固定评估引用及来源，AI叙述仍需内部复核；复核不修改评估判定。
- 公开CVE查询归为风险分析工具，清楚区分公开情报与客户受影响证据。
- 历史结果和旧报告不因资料变化而被覆盖；浏览器验收下钻、比较、报告复核流程。

## 06 Dashboard汇总当前客户资产与风险，并能下钻

**交付：** 首屏汇总当前客户资产、CVE、EOSL风险及覆盖情况，点击数字或图表进入与统计口径一致的明细。

**Blocked by：** 01（在管/删除的统计边界）、02（首屏与模块导航）。

验收：
- 基于已有评估结果实现汇总，不依赖04/05工作区改造；缺少评估时仍可显示资产与覆盖缺口。
- 资产统计按明确对象类型展示，不把主机、软件、容器镜像或组件混为同一数字。
- 展示去重CVE数、受影响对象数、严重程度、EOSL及临近到期、未评估/资料不足、趋势和统计时间。
- 已删除资产默认不计当前纳管风险；历史趋势及固定报告保持原口径，并披露是否包含历史资产。
- 当前选定/有效评估版本与历史运行次数分开，防止重扫重复累计；未知状态单列。
- 图表和列表下钻条件一致，不仅停留在数字卡片；客户切换、空数据、移动端及多对象复用组件验收通过。

## 建议执行顺序

01、02可独立开始；02完成后03、04、05可并行；01与02完成即可开始06。03/04/05不是06的硬阻塞，因为已有资料与评估结果可作为汇总输入。各任务须独立完成必要持久化/API/UI/测试，不能只交付一个页面壳。

本轮不增加真实Linux主机CVE执行器、运行容器扫描执行器、SNMP采集、跨客户Dashboard或NetBox永久删除。这些能力不能因菜单重组而标为已完成。
