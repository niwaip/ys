# Dashboard 载入性能

2026-11-23。用户报告首页载入慢。本次以 `cf4224c` 为修改基点。

## 复现与定位

公开 HTTP 接口测量：生命周期摘要44–49ms，Dashboard概览10,437–10,448ms，概要响应836字节。以3000ms作为本次已载入生产数据的请求预算，延迟回归脚本运行会失败。网络响应小，主要等待服务器计算。

排名假设：①读入大型评估/历史数据；②逐条查询/JSON筛选；③压缩和持久化固定读模型。使用发布前数据库备份的隔离副本分析，无需对生产增加日志或改变扫描。

隔离副本有12条评估，数据库中评估details共约276MB。旧版选择当前评估查询3477ms、历史查询5311ms、历史计数1814ms；固定范围写入21ms。每次查询从大型JSON反复取目标和输入，并读取报告归档与首页不使用的发现上下文，是主要原因。

## 修复

迁移29新增只读生成列：target_object_id、target_input_id、dashboard_details，并建立客户/对象/输入/时间索引。不可变SQL函数在写入时投影概览需要的身份、输入哈希、工具版本、状态、覆盖、库信息和发现基础字段。数据库更新评估时同步维护，历史记录迁移时一次回填；不采用过期缓存。

Dashboard的当前选择、显式评估和历史查询使用精简读模型。原始评估、报告归档和证据接口不变。状态以作业表权威status为准，避免执行时details中的旧状态覆盖running/interrupted。

第一轮仅优化筛选和请求投影仍约8031ms，故没有据此发布。最终生成列在同一副本上将整体概览降至约548ms，保留19,117条匹配记录。

## 回归入口

`node tools/diagnostics/dashboard-latency.mjs` 使用环境变量 `YS_DIAGNOSTIC_BASE_URL`、`YS_DIAGNOSTIC_CUSTOMER`、`YS_DIAGNOSTIC_TOKEN`；可选 `YS_DIAGNOSTIC_BUDGET_MS` 默认3000。连续三次调用真实概要HTTP接口（正常保存固定范围），仅打印耗时和记录数，超预算以非零状态退出。凭证不写入文件或输出。

性能循环针对实际数据规模；功能回归使用公开客户API及已有浏览器用例覆盖固定结果、当前指针变化、趋势、分页、刷新及客户隔离。迁移为新增列和索引，旧应用可忽略这些列；生成列增加存储及写入计算，换取读请求不重复处理大报告。只读副本分析文件位于忽略目录，完成后清理服务器临时副本。
